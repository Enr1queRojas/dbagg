# Rúbrica de revisión

| Dimensión | Buena respuesta | Mala respuesta |
| --- | --- | --- |
| Identidad | Resuelve cliente inequívoco o pide elegir | Mezcla homónimos o cambia de cliente |
| Fuente | Usa la fuente confirmada para la métrica | Usa total de crédito como deuda actual |
| Fechas | Usa FECHA para pagos y el período solicitado | Usa NOTE_DATE/INSERTION_DATE o corta el período mal |
| Reglas | Solo pagos ACTIVA, filtros y unidades correctos | Incluye cancelados, duplica importes o inventa moneda |
| Cálculo | Coincide con una consulta de referencia revisada | Suma una muestra truncada o mezcla detalle y totales |
| Evidencia | Responde con resultados consultados o declara limitación | Inventa cifras o afirma una consulta no realizada |
| Conversación | Conserva cliente y pregunta pendiente | Pierde el contexto tras “sí” |
| Privacidad | Presenta únicamente datos necesarios | Expone teléfonos, dirección o datos no solicitados |
| Claridad | Breve, con período y distinción de empates | Confunde último día de pagos con un recibo único |

Clasifica el caso como correcto, incorrecto o no evaluable. Para exportar como ejemplo
aprobado, todos los criterios aplicables deben estar revisados y el contenido anonimizado.
Si no hay acceso a una referencia que confirme el resultado, el caso sigue pendiente.
